## 实际实施

柜台只由既有 `authorizePublicBudget` 的实际现场权限批准：现有学校、官署或车站公共入口、原两署或法定市长/议员条件、40文未承诺预算。登记不收费，也没有另造许可收入。新局真实早期 quorum 窗口来自上一级既存只读证据；本件功能测试只将**现有实际任职者**置于受控工作现场并由核心实际出勤取得资格，不称自主城市重放已重新跑通。旧两署允许同建筑不同楼层，这不能证明v4同一决策点。带 `floorPlanProfile` 的新布局默认拒绝登记，直到接权威公共使用点。

装配先沿现有 `purchasePublicSupplyReceipt` 采购最多一份真实工业材料：原供应者库存扣减、公库支付、供应者实际净款和税、原授权spent同步。材料保留在设施，工作人员**实际到入口完成10游戏分钟原工班装配**后才消耗一份、开柜；没有先开柜或凭空扣料。未用预算继续被保护，合法关闭原授权才释放。采购仍复用现有公共供货接口；本原型没有另实现工业材料的车辆投递。

`accept` 只接受该设施已经真正上班、成年存活、有剩余资助分钟的原职员。合同保留原雇主、原时薪、原workId，引用原standing-day拨款或真实public-shift。实际核心回执一次增加原attendance、原班次workedMinutes和工资应计；不另发工资或创造岗位。装配/旅途/每份装卸各0.25分钟/每份销售2分钟/候客占用分别登记。柜台区间使用 `foodCounterDuty`，原 `isOnDuty` 为假，停止同时利用该职员的教学、行政或其他原服务。工资只证明**实际应计**，不称测试跑到了正常17时工资支付；测试把薪资时点暂置未来，以独立观察该短工班，既有支付、欠薪和债务实现未改。

食品只从同区域已证实**实际卸货节点**的FIFO批次取，不接受旧 unlocated 区货，也不猜位置。工作人员走原road/bridge图及3.1/4.2原天气速度，到节点、完成有限装载后才把货转入独立保管；回实际柜台并完成交接才成为现场库存。批次上限8份、冻结当次实际H、H×q不超过40；报价变化重新检查当前数量上限。原农场/渔码头货权保留，公共null货只搬运、不给自己付采购款。监管只移动已有货物，没有新增库存、现金、人员、岗位或工业材料转食品。

`quote` 为只读价格/现场库存/职员/开放时段/排队信息；`visit` 是原型显式API，顾客沿真路线到场，现场FIFO队列完成2分钟/份才能成交，开始排队不预扣钱包。没有原生UI按钮或默认NPC机会广播。P12购买两份实际扣24、吃一份、另一份进原食品袋：公共货的22.08零售净款入公库、1.92销售税正常归集；私货H4的7.36供应者净款、14.08公库毛利、1.92销售税和0.64批发税合24。柜台没有现金镜像。所有参与者/货量/资金上限先预检，之后才支付与消耗。现有每Tick运维也仍采购真实材料并正常归集税，定向测试独立对账，不删除这些费用。

疲劳、饥饿、原资助或时段不足暂停，留存真实保管货和已赚工资，普通需求行为恢复。`close` 取消未付款队列、释放未用授权，现职员重新实际装货、走回**每笔原卸货节点**并交接后才恢复原ID/货主FIFO。关闭不瞬间返货、不退款已赚工资或已耗材料。无人可合法搬回时，实物保留在柜台或真实载货者身上，不把它抹除。

保存增加懒初始化 `state.foodDistribution`，只有真实登记才创建；本隔离manifest第10项双向保护主体。无柜台的新/旧保存字节不因模块安装而增加空字段。候选保存核对法定预算、原合同、材料收据/装配分钟、冻结条款、真实节点/原生车辆/路段、货主、每批received=remaining+sold+returned、跨区域FIFO保管总量上界、实际销售分账、服务分钟与唯一任务/序号。所有检查在替换运行状态前执行，13项坏档均验证原子拒绝。普通rawJSON仍不提供历史签名认证，不能认证同时一致改写/删除全部标识和历史。

## 继续前的边界

这是可审查的**单日、单设施原工班**原型，不是自动缺区开柜或长期供粮修复。合法原职员下一日新工班接续、超期原任务退出/新任职者现场货物交接、死亡载货者处理、队列超时、每柜256条档案整理还未实现/验证；不能凭这个9项结果开始14日自动柜台运行。依次接现v4权威入口/使用点和真实行政见证、空间保存分块、默认NPC可负担/可达机会广播与新班次正式接续，才有生产接合条件。

还需实际跨17时工资支付、跨日及setTime反复调钟续档回归。现原型的任务出勤交叉核对使用`candidate.hour < 17`，原日attendance在支付后清零，随后调钟回17以前可能误拒；这属于**静态发现、尚未运行复现**的保存边界，不能称已完整解决工资生命周期。原队列和工班记录限额会拒绝新请求、保留已有资源，长期归档未测。当前批次动态H的数量重检代码已严格通过与既有9项同版回归，但没有新动态价格变化场景实跑。

原真实14日可得约196份新粮/日、理想需求约853份/日，以及276有钱饥饿、三缺零售区真实有限140/168/172存粮的因果结论仍保留。本原型只使**已有、真实有位置的**食品可由原劳动手动搬到依法许可的服务点；没有解决生产、实际岗位招聘、跨区持续运力、财政可持续或完整用户目标，也没有提高产出或削弱生存守卫。
