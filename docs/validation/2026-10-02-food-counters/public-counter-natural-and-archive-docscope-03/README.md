**控制原件的自然失败。** `controlled-natural-v1/` 保留原 fixture SHA `7c9c2da87c4b90fae8a2762498ac6d008727da338ae05da172d2d9aeac3d8386`。17点原职员与两官饥饿约73、随身粮0、commerceAt=1e6。自然过夜，没有 setTime：次日08点饥饿28/28.2，三人均沿真道路赴farm；10点实际抵达，冻结商业前提仍不允许成交。62次原接班/来日班审请求全失败。模块并未伪造健康或资金。旧任务的阶段/lastObservedAt会自然变化，不能称整个任务字节不变；earned与workedMinutes保持。

**玩家救援的有限成功。** `player-rescue-v1/` 使用 headless CPU 的真实 PlayerController KeyW、4.8m/s碰撞行走；不是浏览器正常旅程或GL验收。17点出发，19:05实际走600m到farm，钱包600→568、库存160→156，购4真实吃1留3；实际再走600m回家，23:02近身gift原教师及两官，各消费1。次日08:06教师正常通勤到原school，续 `standing-day-1 / epoch0`；08:58两官真在原hall批准 `public-shift-2`、cap6226.56。10:30同教师沿原330m路把原FIFO8归还，source20→28，柜台关闭。没有改工资、角色、岗位、需求或位置。原476min/43.792保留；现金残差0，食品恰消费4后残差0；full import/export及后24ticks字节完全相同。

**正常城市原件的来源与失败。** `normal-v1-writer-capture/` 在原v1 writer正常createWorld里，只使用speed16、真实tick和合法controller；没有写现金、库存、角色、workId、位置、需求、商业timer或时钟。09:44（extension584）两官142/230在starport-b2批准柜台；原142实购工业材料1份4文、实际装配10min，并真取既有freight-lot-22的8食品。17点其原工资实付43.756664，柜台任务416min/38.251477。捕获原件SHA `6771105fa05ab36eee5b733403e15e583539f2515acbc887a7f50c117c0a1680`。

`normal-v1-natural-migration/` 不救援、不调钟，按此原件自然到次日16点。142/230在17点饥饿39.93/50.43，次日08点0/5.63；他们实际去east-b8/east-b2食店。真实home→食店路网距离2198.63/2392.89m，原home→job只有204.79/381.08m。16点142刚在异区买到食物，230还在路上；24tick后17:36两人都已真实食用，原班审窗口已失。

此处不是冻结商业导致。starport没有食品零售店；原型柜台实存8、0销售，模块尚无NPC消费机会广播与当班真实付费用餐流程。原lot仍是区货20+柜存8=28，货主null、位置与批次未改。原工业材料收到/消耗1、装配10min、支出4均在档内。全局现金残差约1.64e-8；只读几何查询不改变exportSave。没有订阅完整生产/消费事件窗口，所以本分支没有全城实物流量残差，不补算不存在的事件。原工资/分钟保留、full保存和24tick完全精确，但 **正常自然迁移续班断言仍FAIL**。

**256边界的准确范围。** `archive-boundary-first-failed/` 通过合法setTime(16.99)与真实四分之一分钟tick，实际调用256次原17点结算；这是短调度边界测试，绝非256自然日。256存档真实恢复并逐字节相同，第257次抛“柜台结算证据已满”，且在工资入队/清应计之前阻断。此夹具同tick付清，旧queued debt始终0；`oldDebtRetained:true`只是零比较，不能作为旧债保留证据。旧原始记录不改，明确这个限制。
