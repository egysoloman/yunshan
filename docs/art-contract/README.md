# 游戏美术契约（交给体素工坊 / 原生引擎）

`game-art-contract.json` 由 `npx tsx scripts/export-art-contract.ts` 从游戏源码直接导出，不手抄数字。资产要一比一替换游戏几何，必须对上这里的尺寸、原点、朝向和枢轴。

## 共同约定

- 米制、Y 向上；正面 +Z，朝向设施使用点或观看者；原点默认在包围盒最小角。
- 世界体素 0.2m。模型只允许等比缩小（0.9–1），不拉伸、不放大。
- 模型只负责显示。碰撞、行走面、库存和使用点都以游戏数据为准；模型不能占用原本可走的空间，也不能做出游戏里不存在的功能，例如没有信号逻辑的红绿灯。

## 需要美术方补做或修改

1. **床**：床实体高 0.6m，长 2.4m、宽 1.2m。LIFE-035 床头高 1.0m，放不进去。需要一张整体高度不超过 0.6m 的床，或者先由游戏方改床的实体规则。
2. **站台信号杆**：杆上不能自带灯头。实时红灯中心在节点 (+12, +3.9, +11.4)，绿灯在 (+12, +3.15, +11.4)，灯体 0.7×0.55×0.35m。
3. **路口杆**：路口没有信号逻辑，杆上不能出现红黄绿灯。
4. **树**：游戏树高 16–31m（0.2m 量化），树干截面 0.8m。现有的树资产只有 8–14m，需要同一高度族的树。
5. **居民**：契约里列出了 6 个年龄段、站姿和坐姿、近景和远景下每个部件的方盒尺寸和摆动枢轴。CHAR-002 到 015 是作者估计的比例，和这些方盒对不上，还没有接入。
6. **入口灯笼**：入口旁的墙挂灯笼，整体（含托臂、上下盖、灯芯）必须放进沿墙 0.8m、高 1.0m、外挑 0.8m 的包络；最低点不能低于 `max(2.4, 门高−0.4) − 0.6`。BUILT-071 高 1.44m，BUILT-249 高 1.2m，都放不进去。

7. **载具**：游戏载具外形（仅显示，位置与运行由模拟决定）：道路车 宽2.5×长5.5m（车身底 +0.35m、顶约 +2.5m），磁浮/轻轨 3.3×16m，渡船 4.5×11m，缆车 2.5×3.5m（悬挂抬高 2.5m），航班 14×17m；原点在车体中心、+Z 为行进方向。BUILT-170/171/172/173/175 “交通代理变体”只有 48 个三角形，就是游戏现有的三段方盒，没有视觉增益；完整母版 BUILT-280（货运车）、BUILT-281（列车车厢，约 15×29m）、BUILT-284（渡船，约 16.5×14m）、BUILT-285（客机，约 34×32m）尺寸都对不上，不能等比放入。需要按上面的尺寸重新出整车。
