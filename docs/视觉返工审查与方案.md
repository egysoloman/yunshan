## 独立判断

**macro5 仍明确不合参考，也不满足原提示词中“体素风格不等于粗糙堆积”的要求。** 当前差距是大形体、用途体量、街道空间和材料层次共同造成，下一轮不应再以若干 shader 纹理、颜色和门框小件作为视觉收口。

原图 1/2 的重点是交织的街梯、回廊、平台、店铺和真实尺度的人；建筑通过石基座、木构开间、灰石墙、细青瓦、暖窗和绿化组织成街区。原图 3 的书院有院落、前后进深和大台阶，地形是被植被包裹的垂直岩台。原图 4 的桥梁有粗细递进的承力结构，上层轨道和下层生活/产业空间各有尺度。原图 5 的核心是瀑布、水潭、山崖和主建筑群构成一个完整景观，城区和多层峡谷延展，远景仍能读出中式轮廓。

当前主景的右下和中央山坡占据大量画面，坡面连续而空秃，露出白三角；分散的大方盒树冠架在细竖杆上，给人的尺度感接近玩具。所有远建筑几乎都是米黄完整盒体、木框窗带和青绿顶，主阁变成同语言最高一栋。市场和住宅两图有细部，但视觉主导仍是同一款整面奶黄墙、粗绿窗格、厚黑檐和空前坪；市场柜台甚至成为堵住人的大盒，住宅脚下出现粗矩形切面。新增纹理未改变这些主导形状。

## 与像素对应的生成原因

1. `world.ts:82–95` 先用 Gaussian 山体，再把 district 半径 .62 范围和 quarter 70m 内拉平，quarter 外还做 170m 过渡。`world.ts:188–196` 又给每栋楼扩 54m、权重 .82 的肩坡；地质权重在楼边 10m、道路边 12m 内归零，并用 38m/20m 过渡。大量住宅与连接路共同抹平了居住山坡，v3 的 24m 岩柱/8m 台阶主要剩在空区，不足以形成参考的城市悬崖。
2. 当前布局按四个驿站周围六点环和扩圈重试选址 (`world.ts:455–491`)，所有 `rotation=0` (`world.ts:502`)。它避免重叠、连通道路，却没有设计街墙、院落、观瀑平台或沿等高线的城群侧面。道路通过独立入口到驿站的长连接组织，建筑外围自然成为大面积剩余坡地。
3. 主阁中心 x430，水帘中心 x110。主阁宽144m、瀑布宽24m：主阁西实体边 x358 到水帘东边 x122 仍有236m间隔。它们在固定主镜头中相隔很远，不能形成原图 5 的共同主景；单改水着色不会解决。
4. `terrain.ts:99–145` 中 coarse 顶点高度插值，fine 是中心顶面的 stepped 壳；mixed 4/8/16 只在 tile 邻界插入细样本，插入点又分割整个局部 cell。新增内部 T 接头及 fine/coarse 不同边界形状均应逐边复核。白三角首先是拓扑/覆盖回归，不能用云雾、双面材质或埋装饰石遮盖。owner 正在独立 CPU 实网格排查，本文没有自行验证具体根因。
5. 森林近4层、远2层均复用整块 BoxGeometry (`terrain.ts:22,214–235`)，枝冠体积巨大，far 仍画每根细杆。far 两冠高度约为真实树高的 .385，杆宽仅 .8m，正是图中的“方盒 + 火柴棍”。5,200 树全量 far 杆与双冠约需187,200盒三角面，花费不低，仍没有保住连贯的林地轮廓。
6. `renderer.ts:333–381` 为普通楼构造相同的矩形楼板、后墙和窗洞；`architecture-detail.ts:22–38` 仅 core 有不同窗带，其他用途共用统一窗数量、位置和尺度。用途差异主要发生于 `programRoof` 和 `programExterior` 的屋顶/附加小件，主体仍相同。far 将石和木映射为 wall/roof (`renderer.ts:267`)，使不同材料的轮廓更趋一致。
7. 市场外部柜台高1.8m、货物中心高2.1m (`renderer.ts:515–519`)，相对1.72m眼睛明显偏高；家庭花槽、晾衣、小果物的面积很小，无法改变整个20–40m立面和前坪。`architecture-detail.ts:235` 明确仅管理装饰；`types.ts` 和 `access.ts` 当前楼层占用仅矩形 width/depth。不能把渲染里画出院落/通廊就宣称身体已经可以走入。

## 下一批只建议三个大修包

### A. 新旅程 v4 的山崖、局部台地、水景与连续林地

这包改实际世界形体，保留旧四配方，不修改任何旧旅程。建议新增内部可信 `current-v4` 和新的 code-owned terrain recipe 身份；`current-v3` 的地形采样必须完整保留，不只保 legacy/v2。

- 将除机场外的整片 district/quarter 广泛压平，改为连接3–8栋建筑的局部街院台地。台地沿等高线安排，台地边为明确岩崖/石挡墙，肩坡限制在局部12–20m；坡地保留80–240m的大峡谷/山肩形，6–20m岩柱/断面为中尺度，0.2–1.2m破岩/草地仅近区。不是提高现有噪声幅度，也不是在地表埋更多盒石。
- 保612个ID/用途计数/楼层与权限，先固定 market-b0 和 west-b0 的门位与地面高度，便于三张数字机位继续比较。新布局再从街道脊线、平台和院落分配其他实际建筑/节点/道路，重新跑支撑、冲突、连通和坡度验证；不能最后只对 renderer 移楼。
- 把新天枢主阁与前院移到瀑崖侧，水侧实体边与瀑帘退界约40–70m，不盖住落水通道。主阁 x约250–270 为可开始检查的方案，具体以全群碰撞和主镜头确定；不是直接把现阁平移后忽略周围楼/路。新瀑宽48–64m、潭半径60–80m，数据、水床、岸线、交通净空和可见水面一起改变；保153m落差和可用升降/水运。
- 森林改为32m左右的真实林冠群，每簇3–8棵树，近冠由8–12个大小不同的0.2m量化叶簇构成，树有分叉、露根、灌木及树下阴影层。far 保存相邻冠群的占据边界和灰绿层次，在不可分辨距离舍去单独细杆。不能仅增加树总数。近森林改96m懒生成单元，上限建议16个，与建筑驻留相同地真实释放；far 冠面固定预算约40k–60k tri，替换当前约187k的树盒预算，预算为待测目标。

**同镜头验收建议**：保持 core 的数字眼睛/目标/时间/FOV。零白三角/天空漏缝；至少三组能读出顶台、垂直崖面和下层平台的城市断面，高差各≥40m；水帘连续可见≥80%落差，固定1440宽图中主体水帘宽≥40px，潭和下游接合清楚；主阁、水侧平台和瀑布在一组连续结构内。对天空/建筑/道路排除后的“可植树坡地”做独立ID或CPU投影覆盖统计，冠群覆盖目标≥45%，没有孤立火柴棍主导的坡区；最大裸坡连通区面积相对macro5减≥40%。这些百分比是提议的下一批门槛，当前没有声称测过。

### B. 从 far 就能辨认用途的实际建筑体量

先做六个主族，special programs 再派生；612栋复用构件，不复用完整盒楼。各族必须改变基座、主体宽高、屋面组合、院/廊关系和立面开间，材料只是其中一项。

| 用途 | 主导体量和空间 | 材料与尺度 |
| --- | --- | --- |
| 住宅 | 2–3段不同宽度的居住体、局部退台、真实外廊/小庭；高层居住主塔只占部分台地 | 下层灰石/白灰，楼上细木窗、灰青瓦；3–3.4m开间，植物/生活物贴真实阳台 |
| 市场 | 连续小铺 + 高一点的市场主厅，铺前连续檐廊，至少3个能站进去的销售开间 | 0.9–1m柜台、食材架、布篷与少量暖木，石铺地；店牌/货物用现商铺状态 |
| 工坊 | 低宽多跨厂房、锯齿或并列双坡屋顶、侧卸货院、服务塔 | 重石柱、暗木桁架、金属/玻璃天窗，材料架和运输净空；不画假的停运物流 |
| 官署/书院 | 官署为主殿、东西进、门院；书院为低连廊、课堂翼和可进入庭院，二者都不能变成同塔换牌 | 官署厚石基/朱褐柱；书院白灰/暗木/灰瓦；公共院、受控入口仍按原权限 |
| 金融/医疗 | 金融为石基金融厅 + 较窄退台塔；医疗为横向病房/诊疗翼 + 入口雨廊/采光庭 | 银行冷石/青铜/窄竖窗，医馆浅石/白灰/成组宽窗；用途轮廓与室内工作点一致 |
| 交通/滨水 | 驿站为开放候车厅/覆盖平台，码头低木棚与泊位，机场平展航站与塔台，星港为环/发射平台 | 不沿用住宅窗带；梁架、平台、入口、上下车/货运路径具有实际尺寸 |

**最小可落地路径**：已有 `floorFootprints` 可以先实现同一矩形合同内的分层宽深变化；它不能表达 U院、多个翼体、非对称楼板或开放廊道。需要这些空间时新增共享 `floorPlan` 描述（占用矩形/多边形、墙段、开口、固定楼梯、门节点），在 `access/world/controller/renderer` 使用同一描述。`getFloorDimensions` 保作 broadphase 与旧版本回退，不能把视觉空洞留在当前完整碰撞盒中。立面开口和屋顶均从同一 floorPlan 派生，near/far 使用同一主轮廓，far 省窗棂和家具而不省翼体、院口、退台和主要檐脊。

**同镜头验收建议**：core 中检查至少20栋可见建筑，除了主阁高度之外至少6种主轮廓；不给标签、去颜色后仍能由用途结构辨认。market/home 两固定机位必须能凭铺廊/销售开间与居住庭/外廊区分，随机10个局部裁切的人工盲判目标≥80%。保证每个实际楼层仍有通行、可用工作/居住空间；楼层数、地下层、最高公共层及权限包不删减。对新组合建筑实走入口→使用点→上下层→退出，far/near切换保持相同占用轮廓和原子资源释放。形态改造的验收不能只有窗框实例数。

### C. 市场与住宅前30m，作为城市生活的可走空间重建

这包与B共同消掉两张第一人称图中的巨墙、空坪和矩形切面，保持原数字机位；禁止通过调整眼睛方向/距离让画面“改好”。

- 市场重建至少12–18m真实檐廊/街段：左右铺面有开放销售开间，柜台0.9–1m，货物顶≤1.4m，人能看见店内货架/交易场所；3m公共通路和中轴6m入口走廊保净空。用0.2–0.4m宽椽梁和0.2m石板/边沟组织尺度，拆掉主导前景的大实心售台。旧矩形市场可以先保持入口、柜台和室内服务点；新增开放铺面必须共享真实开口/碰撞。
- 住宅重建一个有层次的入口院：正常人尺度门廊、至少2条可进入的外廊/居住入口、石挡墙与边界花木、生活物与窗台。把脚下2m采样跳变做成共享可走的0.2m阶梯/连续坡道与平台，禁止新画薄地板去遮不正确高度。生活物占院侧，留≥3m公共通路；台地和建筑之间没有“进门前跳崖”的矩形切面。
- 白灰、灰石、深木、瓦和玻璃使用各自正确的厚度与结构边界：灰墙分成真实开间，门窗退入墙体，木梁不是横向粗黑条；檐底用梁/椽支撑的可读浅面与阴影层，不是一整块大黑平板。近石面采用0.2–0.6m错缝石块/破边，墙面风化围绕下缘、窗沿和湿区形成区域，而不是所有表面均匀撒噪声。
- 外部摊台、座椅、花槽等纳入共享 site fixtures（位置、体积、碰撞/可用标识），避免现 `programExterior` 只画物件、身体穿过。商品展示读取真实库存；人流只能来自实际NPC位置和路线。可以改善真实通勤/排队路径使人进入视野，不能新增装饰假人群。

**同镜头验收建议**：市场至少3个可辨销售开间、≥5组中尺度生活结构（商品架/摊台/店牌/灯/檐柱/坐处等），住宅至少3种用途明确的入口/外廊/生活结构。每幅前30m视域至少有前景铺地/院界、中景可用门廊、后景建筑三层。连续裸灰墙区不出现宽>4m且高>1.2m的无结构带；市场现黑檐投影面积较macro5降≥40%，靠改厚度/檐廊分段/开间形体实现，不仅抬补光；住宅前坪裸切面零处。1.72m眼高普通WASD实走至少30m并进入市场交易/住宅使用，无遮挡、无穿物、步面正确；旧档门位/层位在旧配方依旧逐字节恢复。

## 实施顺序和证据门槛

1. 白三角先作为独立回归修：实际代理 shared-edge/T接头/fine-coarse边界 CPU 拓扑与相机投影检查，随后在根允许的一个隔离GL实例复验，不与大修混跑。
2. A/B/C先在 `/tmp` 的新版本/几何原型各给 CPU形体、共享占用/净空和预算；根审查后才解冻生产。A的核心崖谷/树群和B的市场/住宅主体必须同时可见，不能再分批小纹理宣告视觉完成。
3. 三张下一轮比较用上表数字坐标、48° FOV、1440×900、12点、balanced；强制pixelRatio=1、关闭动态分辨率只用于像素比较，同时单独记录原默认性能模式的完整color+shadow预算。保存原机位和失败原件。新增街内/院内补充机位单独列出，不替换原比较图。
4. 所有布局变更加可信 `current-v4` recipe 和 fingerprint；完整保留 `legacy-ee3e7a1`、`current-v2-r5`、`current-v2`、`current-v3` 的生成与物理。以至少3个种子的完整world JSON/地形采样/高层地下/路线/编辑/金融保存及24tick精确续演检查旧配方。未知外部标签不能指定任意楼形或地质配方。
5. 保 existing near 建筑 low8/balanced12/high18、细部≤8楼×640实例、fine terrain cache≤18。新far几何替换旧预算，优先减少多余树盒/平箱体；若净新增超过15%完整提交三角/缓冲，提交原因和budget证据后再加。实际当前市场完整约744k tri，不宜不加选择地铺0.2m全世界几何。macOS帧率与长期全社会范围仍须独立验收。
